# CLAUDE.md

Guidance for working on this repository.

## What this is

A browser rhythm sight-reading trainer. It generates random notated rhythms, plays them on a synthesized cowbell, and leaves a silent repeat of the same bar for the user to play back, optionally scoring their taps. See README.md for user-facing behavior.

## Architecture

The entire app is one file, `index.html`, with inline CSS and vanilla JavaScript. There are no dependencies, no build step, and no framework. Keep it that way unless the user asks otherwise. Deployment is GitHub Pages serving the file as-is.

The script is organized into sections, in this order:

- **Rhythm figure library (`GROUPS`)** — the figures the user can pick, in display groups. Each cell has a stable `id` (used for the state input id `fig-<id>` and for saved settings, so do not rename one casually), a weight `w`, a length `beats`, an optional `on` default, and a list of events `{d, g, rest?, flag?, bs?}` where `d` is duration in beats and `g` is a glyph code (`w`, `h`, `dh`, `q`, `dq`, `e`, `de`, `s`, `wr`, `hr`, `qr`, `er`). Cells can carry `beam`, `bracket`, and `tn` (tuplet number). `bs` splits a cell into separate beam subgroups. `ALL_CELLS` flattens the groups. Each figure is in one of three states, held as the value of a hidden input `#fig-<id>`: `off`, `on`, or `must` (guaranteed). `figState`/`setFigState` are the accessors, `selectedCells()` returns everything not `off` and falls back to `[FILL]` (a quarter note) when nothing is on, and `mustCells()` returns the guaranteed ones.
- **Generation** — `layoutMeasure(bpb, cells, must)` is one attempt at a bar: the guaranteed cells each claim a random free slot first, then the gaps between them are filled from the pool, never overrunning the next reserved slot. A cell may only start where its own length divides the beat position (`pos % c.beats === 0`), so 2-beat cells land on odd-numbered beats and odd meters group as 2+2+1. A beat where nothing fits gets `FILL`, so a selection that cannot fill a bar degrades instead of throwing, and a guaranteed cell with nowhere left to go is simply dropped from that attempt. `genMeasure(bpb, cells, must)` runs up to 30 attempts and returns the first with every guarantee placed and at least 2 onsets, otherwise the best scoring one (`got*1000 + (onsets>=2?500:0) + onsets`), so an all-rests or impossible selection still returns a bar. `genRhythm(measures, bpb, cells, must)` hands each guaranteed cell to one measure at random and retries the whole rhythm up to 12 times while any of them has nowhere to go, then flattens cells into events via `cellEvents` and builds the onset list. A guarantee is a promise about the rhythm, so a figure turns up once across a two-measure rhythm rather than once in each measure. The beats per measure ride along on the rhythm as `r.bpb`, and everything downstream reads it from there rather than assuming 4.
- **Notation rendering** — `renderRhythm` builds the staff (barlines, time signature, beat numbers) row by row and calls `drawEvents(events, xf, yf)` for the notation itself; `cellPreview` calls the same `drawEvents` with its own mappers to draw the little figures in the library, so glyph work only has to happen once. Layout is time-proportional: `xOf(beat)` maps a beat position to an x coordinate and `yOf(beat)` to its staff line. `setLayout(bpb, measures)`, called at the top of `renderRhythm`, sets the module-level `LB`, `MW`, `RM` and `PERROW`; since the mappers read those, they are only valid for the rhythm most recently rendered. `PERROW` is where the responsive part lives: under `STACK_UNDER` px of staff width a multi-measure rhythm stacks one measure per row instead of shrinking, and a debounced `resize` listener re-renders when that crosses over. Every row opens with a stacked time signature in the `SIGW` gutter. Beams, partial (secondary) sixteenth beams, tuplet numbers, and quarter-triplet brackets are drawn per beam group; a cell never crosses a barline, so a beam group is always on one row. The SVG contains a `#playhead` line and an empty `#markers` group that scoring appends into.
- **Playhead geometry** — the line does not follow `xOf`. `xOf` leaves `MPAD` of air between a measure's last note and its barline, so a line following it would stall on the closing beat and then teleport 44px into the next measure. `xPlay(beat)` interpolates between beat anchors instead, and where the next beat opens a new measure or a new row it aims at `measureEnd` — the barline — so the sweep is continuous and only ever wraps at the loop point. `yPlay(beat)` picks the row.
- **Figure library UI** — `buildFigs` generates the grid from `GROUPS`; each option is a button `#opt-<id>` wrapping the hidden state input `#fig-<id>` and a status dot. One delegated click handler cycles the state through `NEXT_STATE` (off → on → must → off) and calls `figsChanged`, which syncs, saves, and re-previews. `syncFigs` writes the state back to `data-s` (which drives the dimming, the dot colour and the guaranteed glow), rewrites legacy `true`/`false` values to `on`/`off`, and updates the count in the summary. The `×` on a group clears it, or selects all of it when it is already empty.
- **Phase readout** — a strip along the top of the paper card holds `#stat` (centred) and the loop button (right). `setPhase` writes `PHASE_TEXT`, which is empty for `ready` and for `count`; the count-in is driven from the loop instead, where `showCount(n)` replaces the readout with a fresh `<span>` per beat so the flash animation restarts, with its duration set to one beat. `#loopBtn` is a view of the hidden `#replay` checkbox — the checkbox is still what persists and what Retry reaches for, so anything that changes it must call `syncLoop`.
- **Audio** — Web Audio only. `cowbell` is two square oscillators (562 and 845 Hz) through a bandpass; `click` is a short sine blip. Sounds are written at full scale and `master` carries the single `HEADROOM` scalar, so equal bus gains mean equal loudness; do not reintroduce per-sound level tweaks, since the sliders are meant to be comparable. `killAudio` disconnects `master`, which is how Stop silences already-scheduled sounds; `fadeAudio` is the same thing for retiming, ramping the old graph down over 20 ms and cutting it loose so the swap does not click on a ringing bell. In front of `master` sit two buses: cowbells go through `bellBus` and metronome beats (`met`) through `metBus`, both driven by `syncVol` from the volume sliders and the two hidden mute checkboxes `#bellOn` and `#metronome` (both on by default). Both sounds are always scheduled and only gated by those gains, which is what lets the mute buttons and the sliders affect sound that was scheduled a bar ago; it is the pattern to copy for any other option that gates already-scheduled audio. The count-in and tap clicks stay on `master` so they are always audible.
- **Tempo dial** — the tempo control is a jog wheel, `#dial`, built by `buildDial` (an SVG face of knurls, a track and the `#dialArc` progress arc) with the `‹ ›` nudges and the centre start/stop button laid over it as real buttons. The `#tempo` number input sits on the face and is the single source of truth, so persistence and `startRun` are unchanged; `setTempo` clamps to its `min`/`max` and calls `tempoChanged`, which redraws the arc and, if something is playing, schedules a `retime`. The reading can be typed into where there is a keyboard: `CAN_TYPE` (a `pointer:fine` media query) decides, and on a touch screen the field goes `readOnly` and loses its pointer events so it never eats a turn. `tapTempo` sets the tempo from the spacing of the last few taps on `#tapBtn`, timed on the audio clock like everything else. Turning is relative, not absolute: a pointer drag anywhere on the face accumulates degrees times `BPM_PER_DEG`, so it reads the same wherever you grab it. Because the `‹ ›` sit where a finger naturally lands, a gesture starting on one nudges immediately but turns into a turn after 10° of travel; since the dial captures the pointer, those buttons never see their own `pointerup`, so `endNudge` has to be called from the dial's handler.
- **Screen wake lock** — `keepAwake(on)` holds a `navigator.wakeLock` screen lock for the length of a run, taken in `startRun`, released in `stopAll` and when a single run reaches results. The browser drops the lock whenever the tab is hidden, so a `visibilitychange` listener re-requests it. Everything is guarded: the API is missing on some browsers and the request rejects when the document is not visible.
- **Flow** — `startRun` schedules a count-in of one measure (`scheduleCountIn`) and the first cycle; `scheduleCycle` schedules one rhythm's listen pass plus its optional second-pass sounds and returns `{rhythm, listen, user, end}` times. Both take a `from` cutoff so they can be replayed over a cycle that is already half gone, which is what `retime` uses: on a tempo change it works out the current position in beats, fades the old graph out, re-anchors the cycle so that position is unchanged under the new beat, and schedules only what is still in the future — the pending cycle included. Turning the dial coalesces into one retime through a 140 ms timer, since each one rebuilds the graph. A `requestAnimationFrame` loop (`loop`) drives phase changes, the playhead, and miss detection by comparing `ctx.currentTime` against the cycle times. In continuous mode, the next rhythm is generated and scheduled while the user pass is still running (`state.pending`), then swapped in at the boundary; `nextRhythm` returns the same bar again while `replay` is checked. `state.prev` holds the bar before the current one, which is what Retry reaches for.
- **Retry** — `retryTarget` picks the bar to loop: the one you just played (`state.prev`), or the current one once you are past halfway through your own pass. `retryRun` ticks `replay`, installs that bar, and restarts with `single` forced false so it loops regardless of the continuous setting.
- **Idle preview** — while nothing is running the staff shows what the current settings produce, but only the settings that change what can be generated roll a new bar: `GEN_IDS` (plus `figsChanged`) call `previewIdle`, and everything else merely saves. Start plays the bar already on the staff rather than rolling a fresh one, so the staff is a promise about what you are about to hear.
- **Settings persistence** — `saveSettings`/`loadSettings` write every `input`/`select` with an id, plus the open state of each `details`, to one localStorage key. That includes the hidden inputs, which is how the tempo, the figure states and the two mutes ride along for free; anything new that has to persist should be a hidden input rather than a bespoke key. Older saves stored the figures as booleans, and `syncFigs` converts those on load. Both are wrapped in try/catch because storage throws in the artifact viewer, where the app then simply starts from defaults. Load runs after `buildFigs` so the figure checkboxes exist to restore into.
- **Scoring** — real-time. Each tap is matched greedily to the nearest unhit expected onset within a window (`state.win`, derived from the smallest gap between onsets). Markers are drawn immediately via `addMark`. Scoring is gated on the `score my taps` checkbox (`scoringOn()`), off by default.
- **Calibration** — plays ten clicks at 100 bpm, takes the median tap delay, and writes it into the offset field. The offset in milliseconds is subtracted from taps before matching.

## Rules and gotchas

- All timing must use the Web Audio clock (`ctx.currentTime`). Never time playback or scoring with `Date.now`, `performance.now`, or `setTimeout` beyond rough UI scheduling.
- Settings persist through `localStorage`, but every access must stay inside a try/catch. The file also runs inside the Claude artifact viewer, where storage APIs throw, and the app has to keep working there with defaults.
- Schedule audio ahead of time. Anything scheduled at a timestamp in the past plays immediately and sounds wrong. In continuous mode, the pending cycle exists so its audio is scheduled a full bar early.
- Because of that lead time, a checkbox read inside `scheduleCycle` does not affect audio that is already scheduled, so flipping it mid-run looks dead for up to two bars. If a toggle needs to respond immediately, schedule the sound unconditionally and gate it with a gain node, the way the metronome does.
- Beats per measure is not 4. Read it from `r.bpb` (or `state.rhythm.bpb`) rather than hard-coding a bar length, and remember the count-in, the metronome accent, the beat numbers, and the playhead clamp all depend on it.
- Tuplet durations are fractions like `1/3` and `2/7`, so beat positions accumulate floating point error within a cell. Comparisons on beat positions should use tolerances, not equality.
- Partial sixteenth beams: a stub is drawn only for a sixteenth with no sixteenth on either side, and it points into the group, so it goes right when the sixteenth opens the group and left otherwise. Adjacent sixteenths get a full secondary beam instead. Earlier versions drew a stub past the last sixteenth's stem in the sixteenth-sixteenth-eighth figure, and overhung the first sixteenth's stem in eighth-sixteenth-sixteenth; do not reintroduce either.
- The generator is driven entirely by what the user has selected, so it must survive selections that cannot fill a bar, or that are empty, or that are all rests. Never assume a candidate exists at a given beat position.
- Re-query `#playhead` and `#markers` after any `renderRhythm` call, since rendering replaces the SVG and old element references go stale.
- Figure state lives in the hidden `#fig-<id>` inputs, not in checkboxes, and hidden inputs do not fire `change`. Anything that changes one has to call `figsChanged` itself; the global `document`-level `change` handler will not see it. The same goes for the mute checkboxes and `#tempo`, which is why their handlers call `saveSettings` by hand.
- Anything that changes the tempo has to go through `setTempo`/`tempoChanged` rather than writing `#tempo` directly, or a run in progress will not follow it. Equally, do not call `retime` on every step of a dial turn; it tears down and rebuilds the whole audio graph.
- Do not roll a new rhythm as a side effect. A volume slider, a checkbox, or pressing Start must leave the bar on the staff alone; only `GEN_IDS` and a figure change may call `previewIdle`.
- The playhead has its own mapping (`xPlay`/`yPlay`). Do not move it with `xOf`, which stalls it on the last beat of every measure and then jumps it across the gap to the next one.
- A guaranteed figure is not a promise the generator can always keep: two of them may not fit the same bar, and one can be longer than the bar. `layoutMeasure` drops what does not fit and `genMeasure` scores attempts so the best coverage wins. Do not turn that into an assertion or an infinite retry.
- The `score my taps` checkbox is commented out in the markup while the app is being tried without it, so `scoringOn()` tolerates the element being missing and everything scoring drives (the pad, the legend, the results line, the calibration panel) hides itself through `updateScoringUI`. Keep new scoring-dependent code behind `scoringOn()` rather than reading `$('scoring')` directly, so uncommenting that one line is all it takes to restore the feature.
- The playhead is opt-in through the `moving line` checkbox and off by default; `movePlayhead` returns early and hides it when unchecked.
- The dial's centre button doubles as the user gesture that unlocks audio on mobile, and it is also what takes the wake lock. Any new entry point that plays sound must also come from a user gesture.

## Style

- Match the existing code: vanilla JS, `const`/arrow style, no classes, sections marked with `/* ---------- name ---------- */` comments.
- The app is a light theme: a warm page (`--stage`) with paper cards (`--paper`) and ink text. Colors come from CSS custom properties on `:root`. Use `var(--...)` in both CSS and inline SVG attributes rather than hard-coded hex values; the exceptions are the `#000000xx` overlays used for hairlines and tints, which read correctly on every surface in the palette. `--brass` is a fill colour and is too light for text, so text accents use `--brass-deep`.
- UI copy is plain and literal. Do not add hype words or decorative text.

## Testing

There is no test suite. To check changes:

1. Syntax-check the script block, for example by extracting it and running `node --check`.
2. Open `index.html` in a browser and run a cycle in a few meters and figure selections, including tuplets, to confirm notation renders and audio lines up with the playhead.
3. Turn the dial, hold the `‹ ›`, and check the readout, the arc and the saved tempo agree; then reload and confirm every setting came back.
4. Set a figure to guaranteed and confirm it turns up once somewhere in the rhythm, in both one- and two-measure lengths, and that an impossible guarantee (a 3-beat figure in 2/4) degrades quietly.
5. Change the tempo during a run — by dial, by typing, and by tap tempo — and confirm the music follows without a gap, a click, or a lost downbeat, in the count-in and in both passes.
6. Narrow the window with a two-measure rhythm and confirm the staff restacks one measure per row and the playhead moves down with it.
7. Toggle `score my taps` and confirm the pad, legend, and results appear, taps draw markers in real time, and calibration still fills the offset field.
