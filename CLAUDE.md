# CLAUDE.md

Guidance for working on this repository.

## What this is

A browser rhythm sight-reading trainer. It generates random notated rhythms, plays them on a synthesized cowbell, and leaves a silent repeat of the same bar for the user to play back, optionally scoring their taps. See README.md for user-facing behavior.

## Architecture

The entire app is one file, `index.html`, with inline CSS and vanilla JavaScript. There are no dependencies, no build step, and no framework. Keep it that way unless the user asks otherwise. Deployment is GitHub Pages serving the file as-is.

The script is organized into sections, in this order:

- **Rhythm figure library (`GROUPS`)** — the figures the user can pick, in display groups. Each cell has a stable `id` (used for the state input id `fig-<id>` and for saved settings, so do not rename one casually), a weight `w`, a length `beats`, an optional `on` default, and a list of events `{d, g, rest?, flag?, bs?}` where `d` is duration in beats and `g` is a glyph code (`w`, `h`, `dh`, `q`, `dq`, `e`, `de`, `s`, `x`, `wr`, `hr`, `qr`, `er`). `BEAMS` says how many beams a glyph carries — one for an eighth, two for a sixteenth, three for a thirty-second — and anything absent from it carries one. Cells can carry `beam`, `bracket`, and `tn` (tuplet number). `bs` splits a cell into separate beam subgroups, which is how a sixteenth triplet keeps the eighth beside it out of its beam and out from under its number. The groups are by note value (Basic, Eighths, Sixteenths, 32nds) and then by tuplet (Triplets, 16th Note Triplets, Quintuplets, Septuplets). The `w` and `wr` glyphs are still drawn though no figure uses them, since a bar saved before they were dropped still has to render. `ALL_CELLS` flattens the groups. Each figure is in one of three states, held as the value of a hidden input `#fig-<id>`: `off`, `on`, or `must` (guaranteed). `figState`/`setFigState` are the accessors, `selectedCells()` returns everything not `off` and falls back to `[FILL]` (a quarter note) when nothing is on, and `mustCells()` returns the guaranteed ones.
- **Generation** — `layoutMeasure(bpb, cells, must)` is one attempt at a bar: the guaranteed cells each claim a random free slot first, then the gaps between them are filled from the pool, never overrunning the next reserved slot. A cell may only start where its own length divides the beat position (`pos % c.beats === 0`), so 2-beat cells land on odd-numbered beats and odd meters group as 2+2+1. A beat where nothing fits gets `FILL`, so a selection that cannot fill a bar degrades instead of throwing, and a guaranteed cell with nowhere left to go is simply dropped from that attempt. `genMeasure(bpb, cells, must)` runs up to 30 attempts and returns the first with every guarantee placed and at least 2 onsets, otherwise the best scoring one (`got*1000 + (onsets>=2?500:0) + onsets`), so an all-rests or impossible selection still returns a bar. `genRhythm(measures, bpb, cells, must)` hands each guaranteed cell to one measure at random and retries the whole rhythm up to 12 times while any of them has nowhere to go, then hands the placement to `rhythmFromCells`. A guarantee is a promise about the rhythm, so a figure turns up once across a two-measure rhythm rather than once in each measure. The beats per measure ride along on the rhythm as `r.bpb`, and everything downstream reads it from there rather than assuming 4.
- **What a rhythm is** — `rhythmFromCells(measures, bpb, cells)` is the one way one is built. It takes a list of `{id, start}` (start being a beat position over the whole rhythm), flattens it into events with `cellEvents`, and returns `{measures, bpb, cells, events, onsets}`. The cell list rides along so the beat editor can put a different figure in a slot; `cellById` resolves an id, falling back to `FILL`. Bars saved before the editor existed have only their events, so `rhythmCells(r)` fills `r.cells` in from `cellsFromEvents`, which walks the events and matches each run against the library, longest figure first. That returns `null` for a bar it cannot read, and every caller treats `null` as "this one cannot be edited" rather than an error.
- **Notation rendering** — `staffSvg(r, {live, trim})` builds the staff (barlines, time signature, beat numbers) row by row and calls `drawEvents(events, xf, yf)` for the notation itself, returning the markup; `renderRhythm` sets the layout, writes it into `#score` with `live` on for the playhead and the marker layer, and syncs the star. `trim` crops the empty air above the staff and is what the saved-bar thumbnails use. `cellPreview` calls the same `drawEvents` with its own mappers to draw the little figures in the library, so glyph work only has to happen once. Layout is time-proportional: `xOf(beat)` maps a beat position to an x coordinate and `yOf(beat)` to its staff line. Every beat is the same width, so the beat itself grows for a rhythm that subdivides finely — `setLayout` widens it until the tightest gap in the rhythm gets `MINGAP` px, which leaves anything at a sixteenth or coarser alone and stops eight thirty-seconds piling into one another. The SVG is drawn to fit the card either way, so such a bar simply comes out a little smaller. `setLayout(bpb, measures, r)`, called at the top of `renderRhythm`, sets the module-level `LB`, `MW`, `RM` and `PERROW`; since the mappers read those, they are only valid for the rhythm most recently rendered. `PERROW` is where the responsive part lives: under `STACK_UNDER` px of staff width a multi-measure rhythm stacks one measure per row instead of shrinking, and a debounced `resize` listener re-renders when that crosses over. Every row opens with a stacked time signature in the `SIGW` gutter. Beams, the rows below the primary one, tuplet numbers, and tuplet brackets are drawn per beam group; a cell never crosses a barline, so a beam group is always on one row. The SVG contains a `#playhead` line and an empty `#markers` group that scoring appends into.
- **Playhead geometry** — the line does not follow `xOf`. `xOf` leaves `MPAD` of air between a measure's last note and its barline, so a line following it would stall on the closing beat and then teleport 44px into the next measure. `xPlay(beat)` interpolates between beat anchors instead, and where the next beat opens a new measure or a new row it aims at `measureEnd` — the barline — so the sweep is continuous and only ever wraps at the loop point. `yPlay(beat)` picks the row.
- **Figure library UI** — `buildFigs` generates the grid from `GROUPS`; each option is a button `#opt-<id>` wrapping the hidden state input `#fig-<id>` and a status dot. One delegated click handler cycles the state through `NEXT_STATE` (off → on → must → off) and calls `figsChanged`, which syncs, saves, and re-previews. `syncFigs` writes the state back to `data-s` (which drives the dimming, the dot colour and the guaranteed glow), rewrites legacy `true`/`false` values to `on`/`off`, and updates the count in the summary. The `×` on a group clears it, or selects all of it when it is already empty.
- **Beat editor** — tapping a quarter pulse on the staff opens `#beatPop`, a popover of every figure that could stand in that slot, and picking one swaps it into the bar. `beatHits(r)` lays a `.beathit` rect over every pulse, on top of the notation (hence the inert `#markers`), so a tap on a notehead still finds its beat; `#editsel` is the single tinted rect under them, positioned by `markEditedBeat` from the hit rects it spans, which is why the tint is one shape over a two-beat figure rather than two boxes with a seam. `cellAt(r, beat)` is what a tap means: the figure covering that beat, so a tap anywhere inside a half note edits the half note. `openEditor` offers what `fitsAt` allows — `c.beats <= room`, room being what is left of the measure — as one flat grid in `ALL_CELLS` order, whatever the library's on/off states are, since the user is choosing this one directly. That is deliberately looser than the generator, which also requires `pos % c.beats === 0`: a random bar has to be readable without anyone having asked for it, but a figure the user places by hand may sit where they put it, so a half note can start on beat 2. Nothing is drawn to show it crossing the middle of the bar, because there are no ties; it is simply notated where it is. It carries no group headings and no title: the notation is the label, and `GROUP_OF` supplies the `aria-label` a picture cannot. `replaceCell` drops every cell the new one overlaps and refills whatever that leaves empty with quarter rests, so the bar is always full however the lengths worked out and the beats the user did not ask for stay silent — which means the editor, unlike the generator, can produce a bar of no onsets at all, and everything downstream has to survive one. `applyEdit` installs the result, ticks `replay` the way Retry and `loadFav` do, and reschedules a run in progress. `edit` (`{start, span}`) is the whole of the popover's state, and picking closes it.
- **Phase readout** — a strip along the top of the paper card holds `#stat` (centred) and the loop button (right). `setPhase` writes `PHASE_TEXT`, which is empty for `ready` and for `count`; the count-in is driven from the loop instead, where `showCount(n)` replaces the readout with a fresh `<span>` per beat so the flash animation restarts, with its duration set to one beat. `#loopBtn` is a view of the hidden `#replay` checkbox — the checkbox is still what persists and what Retry reaches for, so anything that changes it must call `syncLoop`.
- **Audio** — Web Audio only. `cowbell` is two square oscillators (562 and 845 Hz) through a bandpass; `click` is a short sine blip. Sounds are written at full scale and `master` carries the single `HEADROOM` scalar, so equal bus gains mean equal loudness; do not reintroduce per-sound level tweaks, since the sliders are meant to be comparable. `killAudio` disconnects `master`, which is how Stop silences already-scheduled sounds; `fadeAudio` is the same thing for retiming, ramping the old graph down over 20 ms and cutting it loose so the swap does not click on a ringing bell. In front of `master` sit three buses: cowbells go through `bellBus`, metronome beats (`met`) through `metBus`, and the quiet second-pass echo through `echoBus`, which hangs off `bellBus` so it follows the rhythm volume and mute. `syncVol` drives all three from the volume sliders, the two hidden mute checkboxes `#bellOn` and `#metronome` (both on by default), and `#echoSound`. Every one of those sounds is scheduled unconditionally and only gated by its gain, which is what lets a control affect sound that was scheduled a bar ago; it is the pattern to copy for any other option that gates already-scheduled audio, in preference to reading a checkbox inside `scheduleCycle`. The count-in and tap clicks stay on `master` so they are always audible.
- **Tempo dial** — the tempo control is a jog wheel, `#dial`, built by `buildDial` (an SVG face of knurls, a track and the `#dialArc` progress arc) with the `‹ ›` nudges and the centre start/stop button laid over it as real buttons. The `#tempo` number input sits on the face and is the single source of truth, so persistence and `startRun` are unchanged; `setTempo` clamps to its `min`/`max` and calls `tempoChanged`, which redraws the arc and, if something is playing, calls `bump`. The reading can be typed into where there is a keyboard: `CAN_TYPE` (a `pointer:fine` media query) decides, and on a touch screen the field goes `readOnly` and loses its pointer events so it never eats a turn. `tapTempo` sets the tempo from the spacing of the last few taps on `#tapBtn`, timed on the audio clock like everything else. Turning is relative, not absolute: a pointer drag anywhere on the face accumulates degrees times `BPM_PER_DEG`, so it reads the same wherever you grab it. Because the `‹ ›` sit where a finger naturally lands, a gesture starting on one nudges immediately but turns into a turn after 10° of travel; since the dial captures the pointer, those buttons never see their own `pointerup`, so `endNudge` has to be called from the dial's handler.
- **Screen wake lock** — `keepAwake(on)` holds a `navigator.wakeLock` screen lock for the length of a run, taken in `startRun`, released in `stopAll`. The browser drops the lock whenever the tab is hidden, so a `visibilitychange` listener re-requests it. Everything is guarded: the API is missing on some browsers and the request rejects when the document is not visible.
- **Flow** — `startRun` schedules a count-in of one measure (`scheduleCountIn`) and the first cycle; `scheduleCycle` schedules one rhythm's listen pass plus its optional second-pass sounds and returns `{rhythm, listen, user, end}` times. Both take a `from` cutoff so they can be replayed over a cycle that is already half gone, which is what `reschedule` uses: it works out the current position in beats, fades the old graph out, re-anchors the cycle so that position is unchanged under the current beat, and lays down only what is still in the future. `fixPending` then decides what the bar in the wings should be — the same bar while `replay` is on, a fresh one when `refresh` says a generation setting moved, otherwise the one already queued. Everything that wants a rebuild goes through `bump(refresh)`, which coalesces into one `reschedule` after 140 ms, since each one tears the graph down. A `requestAnimationFrame` loop (`loop`) drives phase changes, the playhead, and miss detection by comparing `ctx.currentTime` against the cycle times. The run never ends on its own: the next rhythm is generated and scheduled while the user pass is still running (`state.pending`), then swapped in at the boundary. `state.prev` holds the bar before the current one, which is what Retry reaches for.
- **Retry** — `retryTarget` picks the bar to loop: the one you just played (`state.prev`), or the current one once you are past halfway through your own pass. `retryRun` ticks `replay`, installs that bar, and restarts.
- **Idle preview** — while nothing is running the staff shows what the current settings produce, but only the settings that change what can be generated roll a new bar: `GEN_IDS` (plus `figsChanged`) call `previewIdle`, and everything else merely saves. Start rolls a fresh bar too, unless the loop button is on — that is the one setting that means keep the bar you have.
- **Saved bars** — the star at the left of the phase strip keeps the bar on the staff along with the tempo it was read at. They live in their own localStorage key (`FAV_KEY`), newest first, capped at `FAV_MAX`, since the list grows and the settings do not. `favKey` is the identity of a bar — meter, length and notes — so the star is a toggle and knows whether what is on the staff is already saved; the tempo rides along but is not part of the key, or changing the tempo would un-star the bar in front of you. `renderRhythm` calls `syncFav`, so the star follows whatever is on the staff without every caller having to remember. `buildFavs` draws each card with `favSvg`, which points the layout globals at the saved bar, calls `staffSvg` and puts them back. `loadFav` restores the meter, the length and the tempo, ticks `replay` the way Retry does, and restarts the run when one is going.
- **The saved-bars sidebar** — the `X saved` button in the header opens `#favBar`, a fixed drawer down the right. `setFavOpen` is the one way in and out: it drives the `favopen` class on `body`, the button's `aria-expanded`, the hidden `#favOpen` checkbox that persists it, and `relayout`. Past `DOCK_W` the page gives up that width (`body.favopen{padding-right}`) so the drawer sits beside the content and covers nothing; below it the drawer lies over the page with a scrim, and the scrim, `Escape` and loading a bar all close it. `DOCK_W` and the media query in the stylesheet have to agree, and `docks()` is what the script asks. Because docking narrows the staff, `setFavOpen` has to call `relayout`, the same check the `resize` listener runs.
- **Settings persistence** — `saveSettings`/`loadSettings` write every `input`/`select` with an id, plus the open state of each `details`, to one localStorage key. That includes the hidden inputs, which is how the tempo, the figure states and the two mutes ride along for free; anything new that has to persist should be a hidden input rather than a bespoke key. Older saves stored the figures as booleans, and `syncFigs` converts those on load. Both are wrapped in try/catch because storage throws in the artifact viewer, where the app then simply starts from defaults. Load runs after `buildFigs` so the figure checkboxes exist to restore into.
- **Scoring** — real-time. Each tap is matched greedily to the nearest unhit expected onset within a window (`state.win`, derived from the smallest gap between onsets). Markers are drawn immediately via `addMark`. Scoring is gated on the `score my taps` checkbox (`scoringOn()`), off by default.
- **Calibration** — plays ten clicks at 100 bpm, takes the median tap delay, and writes it into the offset field. The offset in milliseconds is subtracted from taps before matching.

## Rules and gotchas

- All timing must use the Web Audio clock (`ctx.currentTime`). Never time playback or scoring with `Date.now`, `performance.now`, or `setTimeout` beyond rough UI scheduling.
- Settings persist through `localStorage`, but every access must stay inside a try/catch. The file also runs inside the Claude artifact viewer, where storage APIs throw, and the app has to keep working there with defaults.
- Schedule audio ahead of time. Anything scheduled at a timestamp in the past plays immediately and sounds wrong. The pending cycle exists so its audio is scheduled a full bar early.
- Because of that lead time, a control read inside `scheduleCycle` does not affect audio that is already scheduled, so flipping it mid-run looks dead for up to two bars. Every setting is expected to reach the sound at once. Where a sound can simply be gated, schedule it unconditionally and put a gain node in front, the way `metBus` and `echoBus` do. Where the change alters *what* is played rather than whether it is heard, call `bump` so the schedule is laid down again — `bump(true)` if it changes what the generator can produce.
- Beats per measure is not 4. Read it from `r.bpb` (or `state.rhythm.bpb`) rather than hard-coding a bar length, and remember the count-in, the metronome accent, the beat numbers, and the playhead clamp all depend on it.
- Tuplet durations are fractions like `1/3` and `2/7`, so beat positions accumulate floating point error within a cell. Comparisons on beat positions should use tolerances, not equality.
- A tuplet with a rest in it cannot be beamed, so it carries `bracket` rather than `beam`, and its eighths need `flag:true` since nothing else gives them one. `drawEvents` keeps two lists for that reason: `groups` holds the sounding notes, which is what a beam joins, and `spans` holds every event of a group including rests, which is what a bracket has to reach across — a broken triplet's bracket would otherwise stop short of the partial it silenced.
- A broken triplet is a silenced partial, never a longer note swallowing two of them. Every partial keeps the value it has in the whole triplet, so the reader sees the grid instead of counting a quarter out of it; a quarter-then-eighth triplet is exactly what this library does not have.
- Beam rows below the primary: a row runs full between neighbours that both reach that deep, and a note whose neighbours do not gets a stub instead, pointing into the group — right where it opens the group, left otherwise. Adjacent sixteenths get a full secondary beam instead. Earlier versions drew a stub past the last sixteenth's stem in the sixteenth-sixteenth-eighth figure, and overhung the first sixteenth's stem in eighth-sixteenth-sixteenth; do not reintroduce either.
- The generator is driven entirely by what the user has selected, so it must survive selections that cannot fill a bar, or that are empty, or that are all rests. Never assume a candidate exists at a given beat position.
- Re-query `#playhead`, `#markers` and the beat hit rects after any `renderRhythm` call, since rendering replaces the SVG and old element references go stale. That is why the open beat's tint is reapplied by `markEditedBeat` from `renderRhythm` rather than held on an element.
- The beat editor is anchored to a beat on the screen, so anything that moves that beat or replaces the bar under it has to call `closeEditor`: rolling a new bar, loading a saved one, restacking the staff, starting a run, and the bar swap at a cycle boundary all do.
- The alignment rule (`pos % c.beats === 0`) is the generator's, not the app's. `layoutMeasure` enforces it and `fitsAt` does not, so a bar can hold a figure at a position the generator would never have chosen, and anything reasoning about cell positions has to cope with that — `cellsFromEvents` reading a saved bar back included. The one rule that does hold everywhere is that a cell never crosses a barline.
- Build a rhythm with `rhythmFromCells` rather than assembling `events` by hand, or it will arrive without the cell list and the editor will have to guess it back from the notes.
- `LB`, `MW`, `RM` and `PERROW` describe the rhythm on the staff, and `xOf`/`yOf`/`xPlay` read them. Anything that draws a different rhythm — the saved-bar thumbnails — has to put them back afterwards, or the playhead and the scoring marks will be laid out for the wrong bar.
- `loadFav` writes `#measures` and `#timesig` directly, which fires no `change` event, so it saves the settings itself. It deliberately does not roll a new bar; the whole point is the bar it just installed.
- Anything that changes how much width the staff has — the window resizing, the sidebar docking — has to go through `relayout`, or a two-measure rhythm will keep the stacking it had before. The sidebar's open state is only restored on load where it docks, since coming back to a page hidden under an overlay is not a welcome.
- Figure state lives in the hidden `#fig-<id>` inputs, not in checkboxes, and hidden inputs do not fire `change`. Anything that changes one has to call `figsChanged` itself; the global `document`-level `change` handler will not see it. The same goes for the mute checkboxes and `#tempo`, which is why their handlers call `saveSettings` by hand.
- Anything that changes the tempo has to go through `setTempo`/`tempoChanged` rather than writing `#tempo` directly, or a run in progress will not follow it. Equally, do not call `retime` on every step of a dial turn; it tears down and rebuilds the whole audio graph.
- Do not roll a new rhythm as a side effect. A volume slider or a checkbox must leave the bar on the staff alone; only `GEN_IDS`, a figure change, and Start itself may roll one.
- The playhead has its own mapping (`xPlay`/`yPlay`). Do not move it with `xOf`, which stalls it on the last beat of every measure and then jumps it across the gap to the next one.
- A guaranteed figure is not a promise the generator can always keep: two of them may not fit the same bar, and one can be longer than the bar. `layoutMeasure` drops what does not fit and `genMeasure` scores attempts so the best coverage wins. Do not turn that into an assertion or an infinite retry.
- The `score my taps` checkbox is commented out in the markup while the app is being tried without it, so `scoringOn()` tolerates the element being missing and everything scoring drives (the pad, the legend, the results line, the calibration panel, the `sound on my taps` field) hides itself through `updateScoringUI`. Keep new scoring-dependent code behind `scoringOn()` rather than reading `$('scoring')` directly, so uncommenting that one line is all it takes to restore the feature.
- The playhead is opt-in through the `moving line` checkbox and off by default; `movePlayhead` returns early and hides it when unchecked.
- The dial's centre button doubles as the user gesture that unlocks audio on mobile, and it is also what takes the wake lock. Any new entry point that plays sound must also come from a user gesture.

## Style

- Match the existing code: vanilla JS, `const`/arrow style, no classes, sections marked with `/* ---------- name ---------- */` comments.
- The app is a light theme: a warm page (`--stage`) with paper cards (`--paper`) and ink text. Colors come from CSS custom properties on `:root`. Use `var(--...)` in both CSS and inline SVG attributes rather than hard-coded hex values; the exceptions are the `#000000xx` overlays used for hairlines and tints, which read correctly on every surface in the palette. `--brass` is a fill colour and is too light for text, so text accents use `--brass-deep`.
- UI copy is plain and literal. Do not add hype words or decorative text.

## Testing

There is no test suite. To check changes:

1. Syntax-check the script block, for example by extracting it and running `node --check`.
2. Open `index.html` in a browser and run a cycle in a few meters and figure selections, including tuplets, to confirm notation renders and audio lines up with the playhead.
3. Turn the dial, hold the `‹ ›`, and check the readout, the arc and the saved tempo agree; then reload and confirm every setting came back.
4. Set a figure to guaranteed and confirm it turns up once somewhere in the rhythm, in both one- and two-measure lengths, and that an impossible guarantee (a 3-beat figure in 2/4) degrades quietly.
5. Change the tempo during a run — by dial, by typing, and by tap tempo — and confirm the music follows without a gap, a click, or a lost downbeat, in the count-in and in both passes.
6. Narrow the window with a two-measure rhythm and confirm the staff restacks one measure per row and the playhead moves down with it.
7. Tap a beat, swap the figure on it, and confirm the bar still fills the measure — including replacing a long figure with a short one and the other way round, in an odd meter, and in the second measure. Do it during a run and confirm the sound follows within the bar, then load a bar saved before the change and confirm it can still be edited.
8. Toggle `score my taps` and confirm the pad, legend, and results appear, taps draw markers in real time, and calibration still fills the offset field.
